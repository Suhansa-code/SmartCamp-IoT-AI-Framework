What is SDRC-Box?

An integrated IoT + AI framework for rapid deployment in disaster-stricken areas. It connects ESP32 sensor nodes to an edge gateway (Intel NUC) for flood prediction, a Raspberry Pi 5 for camp management + PAGES psycho-educational system, and an AWS cloud platform for centralized admin dashboards. The research novelty is SAAMP (Semantic-Aware Adaptive Message Prioritization) for reliable IoT communication under degraded network conditions.

Tech Stack

Edge/Middleware: Python 3.11, FastAPI, Flask, GeoPandas, NetworkX
ML/AI: XGBoost, scikit-learn, LightGBM, Isolation Forest, Ridge, Joblib
Camp Server: Node.js, Express, React 18 + Vite, SQLite (better-sqlite3)
Cloud: Next.js 16, React 19, Express, Turso/libSQL, Recharts
IoT: MQTT (EMQX Serverless), ESP32 (Arduino/C++, planned)
Infra: GitHub Actions, Tailwind CSS 4, Framer Motion

Integration 3 pathways

How the three platforms connect, communicate, and share data across the SDRC-Box system.

1. Edge Gateway → Cloud Platform (MQTT + REST)

Integration Prompt

The Edge Gateway (Intel NUC) runs the FastAPI hydrospatial service on :8000 and the XGBoost flood prediction model. Environmental sensor data (rainfall, water level, GPS coordinates) is collected locally. Flood risk predictions are published as MQTT messages (QoS 2, CRITICAL priority) to the EMQX broker under smartcamp/flood/. The Cloud Platform subscribes to this topic via its MQTT client (services/mqtt.js) and surfaces alerts in the Disaster Dashboard.

Integration Points
  • • MQTT Topic: smartcamp/flood/#
  • • Protocol: MQTTS :8883 via EMQX Serverless
  • • QoS: 2 (CRITICAL flood alerts)
  • • Consumer: floodPredictionService.js
  • • REST Alternative: Edge hydrospatial API at :8000 for on-demand river/station/weather data

2. Raspberry Platform → Cloud Platform (SAAMP MQTT + REST)

Integration Prompt

The Raspberry Pi runs two Express servers: res-mng_backend (:5000) for camp operations and pages-backend (:3001) for education. All camp events (registration, check-in, distribution, wristband issuance) are published through the SAAMP MQTT layer (saampMqtt.js) which classifies messages by semantic priority, adapts QoS based on network state, and buffers offline. The Cloud Platform's campDataService.js subscribes to smartcamp/# and maintains the in-memory camp state. Resource forecast requests go via REST: RPi → POST /api/predict → Cloud prediction service.

Integration Points
  • • MQTT Topics: smartcamp/{registration,checkin,distribution,wristband,network,prediction}/#
  • • SAAMP Priorities: CRITICAL (QoS 2) / HIGH (QoS 1-2) / MEDIUM (QoS 1) / LOW (QoS 0)
  • • Offline Buffer: SQLite mqtt_buffer table, flushed on reconnect
  • • REST APIs: RPi :5000/api/prediction → Cloud :3001/api/predict
  • • EMQX Manager: emqxManager.js creates per-person MQTT credentials via EMQX REST API

3. Raspberry Platform (Internal) — PAGES Edu System Integration

Integration Prompt

The PAGES system is fully contained on the Raspberry Pi. The React frontend communicates with the PAGES Express backend (:3001) via REST for session creation, child lookup, and scoring. The backend stores session data in SQLite/Turso and calls the Flask ML service (:5001) for Z-score + Isolation Forest anomaly detection after each game session. The gate decision (PASS/FAIL_FIRST/FAILED_CONFIRMED) determines the child's next activity. Welfare anomaly alerts generated by the alertService.js are synced to the Cloud Platform for the admin welfare dashboard.

Integration Points
  • • Frontend → Backend: REST /api/child, /api/session, /api/dashboard
  • • Backend → Flask ML: POST :5001/score for anomaly detection
  • • Database: Local Turso/SQLite (pages.db)
  • • Cloud Sync: syncService.js forwards welfare alerts to Cloud Platform
  • • Offline Mode: Sessions stored locally, synced when connectivity available

Communication Protocol

Sensors → Serial/UART → Edge Gateway → MQTTS :8883 → EMQX Broker → RPi & Cloud VM. The RPi uses the SAAMP protocol layer for adaptive QoS and offline buffering. Cloud-to-cloud communication uses HTTPS (REST). The PAGES system runs locally on the RPi with the Flask ML service for anomaly detection.
